# Sure Tagger 语言层 Pipeline 汇报文档

本文档用于汇报当前 meeting-level 语言层 tagging pipeline 的用途、使用方式和新数据集接入方式。

项目路径：

```text
/hpc_stor03/sjtu_home/huifei.wang/sure-tagger
```

当前样板数据集：

```text
/hpc_stor03/sjtu_home/huifei.wang/sure-tagger/AMI
```

## 1. Pipeline 目标

该 pipeline 将原始 ASR / 会议转写数据统一转换成标准 manifest，再按会议粒度生成语言层标签。

当前最终输出粒度是 meeting：一场会议对应一条 tag 结果，而不是一个 segment 对应一条结果。

支持的标签：

| 标签 | 作用 | 是否需要 API |
| --- | --- | --- |
| `language` | 判断文本语言 | 否 |
| `word_count` | 统计词数、字符数、token 数 | 否 |
| `punctuation` | 统计标点和终止标点 | 否 |
| `filler` | 统计 `uh`、`um`、`ah` 等填充词 | 否 |
| `repetition` | 检测连续词语重复 | 否 |
| `topic` | 输出层级主题标签、关键词、专有名词 | 是，或用 heuristic 离线验证 |

## 2. 整体流程

```text
原始数据集
  -> build-manifest
  -> segment_manifest.jsonl
  -> build-meeting-manifest
  -> meeting_manifest.jsonl
  -> tag
  -> meeting_tags.jsonl
  -> inspect / report
  -> QA 抽样文件和运行报告
```

阶段说明：

| 阶段 | 输入 | 输出 | 作用 |
| --- | --- | --- | --- |
| `build-manifest` | 原始数据集目录 | `segment_manifest.*.jsonl` | 将不同数据集转成统一 segment manifest |
| `build-meeting-manifest` | segment manifest | `meeting_manifest.*.jsonl` | 按 `meeting_id` 聚合成会议级输入 |
| `tag` | meeting manifest | `meeting_tags.*.jsonl` | 对每场会议生成语言层 tags |
| `inspect` | meeting manifest + tags | `meeting_qa_samples.*.jsonl` | 生成可人工检查的抽样文件 |
| `report` | 各阶段运行过程 | `*.report.json` | 保存处理数量、失败数量和标签分布 |

## 3. 当前代码结构

```text
sure_tagger/
  cli.py                  # CLI 入口
  schemas.py              # manifest / tag / error 基础结构
  meeting_manifest.py     # segment 到 meeting 的聚合逻辑
  datasets/ami.py         # AMI 数据集 adapter
  tags/                   # 各类 tag tool
  text/                   # 文本清洗、tokenizer、topic 上下文
  llm/                    # topic API client、cache、prompt
  report.py               # 运行报告

configs/
  ami.yaml
  tags_language_mvp.yaml
  topic_taxonomy_general.yaml
  topic_response_schema.json
```

当前 CLI 中已注册的数据集是 `ami`。如果新增数据集，需要增加 adapter 并在 `cli.py` 中注册。

## 4. 标准输入输出

### 4.1 Segment Manifest

`segment_manifest.*.jsonl` 是底层解析结果，一行一个 segment。后续聚合依赖它的统一字段。

最小字段：

```text
corpus.dataset_name
sample.sample_id
sample.audio.path
sample.audio.start_sec
sample.audio.end_sec
sample.text.transcript
sample.native_metadata.meeting_id
sample.native_metadata.speaker_id
sample.provenance.source_path
```

其中 `meeting_id` 是 meeting 聚合的关键字段。

### 4.2 Meeting Manifest

`meeting_manifest.*.jsonl` 是 tagger 的标准输入，一行一场会议。

关键字段：

```text
sample.sample_id
sample.audio.path
sample.audio.start_sec
sample.audio.end_sec
sample.text.transcript
sample.text.normalized_transcript
sample.text.speaker_labeled_transcript
sample.native_metadata.granularity = meeting
sample.native_metadata.meeting_id
sample.native_metadata.source_sample_count
sample.native_metadata.speaker_ids
```

字段用途：

- `sample.text.transcript`: 确定性 tags 的主要输入。
- `sample.text.speaker_labeled_transcript`: topic prompt 优先使用的输入。
- `sample.native_metadata`: 保存会议 ID、speaker 列表、segment 数量等信息。
- `sample.provenance`: 保存来源文件，便于回溯。

### 4.3 Tag Result

`meeting_tags.*.jsonl` 每行对应一场会议。

每个 tag 结果包含：

```text
value
confidence
method
tool_version
reliability
details
```

这样可以同时记录标签值、置信度、生成方法和工具版本，方便后续比较和回溯。

## 5. Pipeline 怎么用

所有命令在项目根目录执行：

```bash
cd /hpc_stor03/sjtu_home/huifei.wang/sure-tagger
```

### 5.1 一条命令跑完整流程

默认只跑确定性 tags，不调用大模型：

```bash
python3 -m sure_tagger.cli run-meeting-pipeline \
  --dataset ami \
  --root /hpc_stor03/sjtu_home/huifei.wang/sure-tagger/AMI \
  --output-dir outputs/ami \
  --run-name full.deterministic
```

如果需要 topic，但先不调用 API，可以用 heuristic 离线验证：

```bash
python3 -m sure_tagger.cli run-meeting-pipeline \
  --dataset ami \
  --root /hpc_stor03/sjtu_home/huifei.wang/sure-tagger/AMI \
  --output-dir outputs/ami \
  --run-name full.topic.heuristic \
  --include-topic \
  --topic-provider heuristic
```

如果需要调用配置中的 `gpt-5.5` 跑 topic：

```bash
python3 -m sure_tagger.cli run-meeting-pipeline \
  --dataset ami \
  --root /hpc_stor03/sjtu_home/huifei.wang/sure-tagger/AMI \
  --output-dir outputs/ami \
  --run-name full.topic.gpt55 \
  --include-topic
```

该命令会自动生成：

```text
outputs/ami/segment_manifest.<run-name>.jsonl
outputs/ami/meeting_manifest.<run-name>.jsonl
outputs/ami/meeting_tags.<run-name>.jsonl
outputs/ami/meeting_qa_samples.<run-name>.jsonl
outputs/ami/pipeline.<run-name>.report.json
```

常用参数：

| 参数 | 作用 |
| --- | --- |
| `--dataset` | 指定数据集 adapter，当前为 `ami` |
| `--root` | 原始数据集根目录 |
| `--output-dir` | 中间产物、最终结果和报告输出目录 |
| `--run-name` | 本次运行名称，会进入输出文件名 |
| `--meetings` | 只处理指定会议，例如 `ES2002a,ES2005a` |
| `--tags` | 手动指定 tags，例如 `language,word_count` |
| `--include-topic` | 在默认确定性 tags 外追加 `topic` |
| `--topic-provider heuristic` | 不调用 API，使用启发式 topic 验证流程 |
| `--meeting-limit` | 只处理前 N 场会议，用于抽样 |
| `--qa-sample-size` | QA 抽样数量，默认 20 |
| `--skip-qa` | 不生成 QA 抽样文件 |

注意：`--segment-limit` 只适合调试 parser。正式 meeting tag 不建议使用，因为它会截断同一场会议的 segment。

### 5.2 分步执行

如果需要单独检查每个阶段，可以分步执行。

生成 segment manifest：

```bash
python3 -m sure_tagger.cli build-manifest \
  --dataset ami \
  --root /hpc_stor03/sjtu_home/huifei.wang/sure-tagger/AMI \
  --output outputs/ami/segment_manifest.full.jsonl \
  --bad-samples outputs/ami/bad_samples.build_segment_manifest.full.jsonl \
  --report outputs/ami/build_segment_manifest.full.report.json
```

聚合 meeting manifest：

```bash
python3 -m sure_tagger.cli build-meeting-manifest \
  --manifest outputs/ami/segment_manifest.full.jsonl \
  --output outputs/ami/meeting_manifest.full.jsonl \
  --bad-samples outputs/ami/bad_samples.build_meeting_manifest.full.jsonl \
  --report outputs/ami/build_meeting_manifest.full.report.json
```

跑确定性语言 tags：

```bash
python3 -m sure_tagger.cli tag \
  --manifest outputs/ami/meeting_manifest.full.jsonl \
  --config configs/tags_language_mvp.yaml \
  --tags language,word_count,punctuation,filler,repetition \
  --output outputs/ami/meeting_language_tags.full.deterministic.jsonl \
  --bad-samples outputs/ami/bad_samples.tag.meeting.full.deterministic.jsonl \
  --report outputs/ami/tag.meeting.full.deterministic.report.json
```

抽样跑 topic，不调用 API：

```bash
python3 -m sure_tagger.cli tag \
  --manifest outputs/ami/meeting_manifest.full.jsonl \
  --config configs/tags_language_mvp.yaml \
  --tags topic \
  --topic-provider heuristic \
  --limit 20 \
  --output outputs/ami/meeting_language_tags.topic.heuristic.sample20.jsonl \
  --report outputs/ami/tag.meeting.topic.heuristic.sample20.report.json
```

抽样调用 `gpt-5.5` 跑 topic：

```bash
python3 -m sure_tagger.cli tag \
  --manifest outputs/ami/meeting_manifest.full.jsonl \
  --config configs/tags_language_mvp.yaml \
  --tags topic \
  --limit 20 \
  --output outputs/ami/meeting_language_tags.topic.gpt55.sample20.jsonl \
  --bad-samples outputs/ami/bad_samples.tag.meeting.topic.gpt55.sample20.jsonl \
  --report outputs/ami/tag.meeting.topic.gpt55.sample20.report.json
```

生成 QA 抽样：

```bash
python3 -m sure_tagger.cli inspect \
  --manifest outputs/ami/meeting_manifest.full.jsonl \
  --tags-file outputs/ami/meeting_language_tags.full.deterministic.jsonl \
  --sample-size 20 \
  --output outputs/ami/meeting_qa_samples.20.jsonl
```

## 6. 配置和 API

主配置文件：

```text
configs/tags_language_mvp.yaml
```

topic taxonomy：

```text
configs/topic_taxonomy_general.yaml
```

topic 返回结构：

```text
configs/topic_response_schema.json
```

topic 当前使用 OpenAI-compatible Responses API。默认从以下位置读取 key 和网关配置：

```text
api_key_path: api.txt
model_provider: apifusion
codex_config_path: /hpc_stor03/sjtu_home/huifei.wang/.codex/config.toml
```

`api.txt` 保存 API key，已加入 `.gitignore`，不要打印或提交。

API key 读取优先级：

```text
OPENAI_API_KEY
  -> configs/tags_language_mvp.yaml 中的 api_key_path
  -> .codex/config.toml 中 provider env 的 OPENAI_API_KEY
```

base URL 读取优先级：

```text
OPENAI_BASE_URL
  -> configs/tags_language_mvp.yaml 中的 base_url
  -> .codex/config.toml 中 model_providers.<provider>.base_url
  -> https://api.openai.com/v1
```

正式全量跑 topic 前，建议先用 `--limit 20` 抽样确认 API、费用、速率和标签质量。

## 7. 新数据集如何接入

接入新数据集时，不需要重写 `tags/` 下面的 tag tools。核心工作是新增一个 dataset adapter，将新数据集的原始结构转换为统一的 segment manifest。

### 7.1 新数据集需要满足的条件

新增数据集建议满足以下条件：

1. 有可读取的转写文本，至少能切分到 utterance / segment 级别。
2. 每条 segment 能归属到稳定的 `meeting_id`、`session_id` 或等价分组 ID；如果原始数据没有会议概念，需要先定义清楚聚合规则。
3. 每条 segment 最好有 `speaker_id`，这样 meeting 文本可以生成 speaker-labeled transcript；没有 speaker 时也可以接入，但 topic 和 QA 可解释性会下降。
4. 每条 segment 最好有开始和结束时间，单位统一为秒；没有时间戳时需要约定 fallback，否则音频定位和会议时长统计会不完整。
5. 原始音频路径需要能在集群上稳定解析；如果只有文本，也需要在 `sample.audio.path` 中给出可追溯的占位或来源路径。
6. 文本需要能规范化为 UTF-8 字符串，空文本、坏样本和解析失败样本要能写入 `bad_samples.*.jsonl`。
7. 数据集应能提供来源信息，例如原始文件路径、split、版本或 annotation release，方便后续审计和复现。
8. 许可和数据访问权限需要允许在当前环境中读取、生成中间文件和做模型调用。

只要 adapter 能输出符合 schema 的 segment manifest，后续的 meeting 聚合、确定性 tags、topic、QA 和 report 都可以复用。

### 7.2 Adapter 输出要求

新 adapter 输出的每条 segment record 至少包含：

```text
corpus.dataset_name
corpus.native_metadata
sample.sample_id
sample.audio.path
sample.audio.start_sec
sample.audio.end_sec
sample.text.transcript
sample.text.normalized_transcript
sample.native_metadata.meeting_id
sample.native_metadata.speaker_id
sample.provenance.source_path
sample.provenance.source_split
```

建议 `sample.sample_id` 使用稳定格式，例如：

```text
<DATASET>:<meeting_id>:<speaker_id>:<segment_id>
```

meeting 聚合后会自动生成：

```text
sample.text.speaker_labeled_transcript
sample.native_metadata.granularity = meeting
sample.native_metadata.source_sample_count
sample.native_metadata.speaker_ids
```

### 7.3 接入步骤

1. 在 `sure_tagger/datasets/` 下新增 `<dataset>.py`。
2. 实现 `build_manifest(root, output_writer, bad_writer=None, limit=None, meetings=None)`。
3. 在 adapter 中完成原始文本、音频路径、时间戳、speaker 和 provenance 的解析。
4. 在 `sure_tagger/cli.py` 的 `build-manifest` 和 `run-meeting-pipeline` 分支注册新数据集名称。
5. 先跑一个 meeting ID，确认 segment manifest 和 meeting manifest 正常。
6. 再跑 deterministic tags，确认无异常或只有可解释的 bad samples。
7. 用 `--topic-provider heuristic` 抽样验证 topic 流程。
8. 人工 QA 通过后，再抽样调用 API。
9. API 抽样质量稳定后，再全量运行。

新数据集接入后的推荐验证命令形态：

```bash
python3 -m sure_tagger.cli run-meeting-pipeline \
  --dataset <dataset> \
  --root <dataset_root> \
  --meetings <meeting_id> \
  --output-dir outputs/<dataset> \
  --run-name <dataset>.one_meeting.deterministic
```

```bash
python3 -m sure_tagger.cli run-meeting-pipeline \
  --dataset <dataset> \
  --root <dataset_root> \
  --meetings <meeting_id> \
  --output-dir outputs/<dataset> \
  --run-name <dataset>.one_meeting.topic.heuristic \
  --include-topic \
  --topic-provider heuristic
```

## 8. 输出文件说明

常见输出：

```text
segment_manifest.*.jsonl                 # segment 级解析结果
meeting_manifest.*.jsonl                 # meeting 级 tag 输入
meeting_tags.*.jsonl                     # 一条命令生成的 meeting tags
meeting_language_tags.*.jsonl            # 分步 tag 输出
bad_samples.*.jsonl                      # 失败或异常样本
*.report.json                            # 各阶段运行统计
meeting_qa_samples.*.jsonl               # 人工 QA 抽样
```

其中 `pipeline.*.report.json` 是 `run-meeting-pipeline` 的总报告，会记录 segment、meeting、tag 三个阶段的统计和输出路径。

## 11. 当前限制

1. `language` 当前是 Unicode script heuristic，不是 fastText / CLD3。
2. `topic` fallback 是启发式，只用于离线工程验证，不应作为最终高质量 topic 标签。
3. 当前 `apifusion` 网关对 Responses API `json_schema` 格式不稳定，因此默认使用 `json_object` 并在本地校验 taxonomy。
4. AMI 当前只处理音频和语言层 XML 标注，没有处理视频。
5. 输出文件可能较大，全量运行前应确认磁盘空间。
